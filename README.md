# Тихий двір — система керування готелями

Навчальний вебзастосунок для щоденної роботи однієї мережі готелів: від пошуку вільного номера й бронювання до заселення, клінінгу та перегляду валового доходу. Інтерфейс українською, адаптований насамперед для смартфона й доповнений компонуванням для десктопа.

Курсова робота з дисципліни **«Вебтехнології»** на тему **«Система керування готелями»**.

## Основні можливості

| Роль | Можливості |
| --- | --- |
| **Адмін** — адміністратор системи | Створення й редагування готелів; створення користувачів усіх ролей — Адмінів, Адміністраторів і Керуючих; призначення Керуючих готелям. |
| **Адміністратор** — адміністратор мережі | Пошук за датами, готелем і кількістю ліжок; створення, зміна дат і скасування бронювань; календар; дохід окремого готелю або всієї мережі. |
| **Керуючий** — адміністратор готелю | Номери свого готелю, ціни й оснащення; заселення, виселення, завершення клінінгу; календар, бронювання та дохід свого готелю. |

Пошук окремо показує номери з точною кількістю ліжок і просторіші варіанти. Календар поєднує майбутні бронювання з фактичним станом та підсвічує накладки. Для оснащення доступні чайник, кондиціонер, телевізор і холодильник.

Гості, оплати, витрати та інші працівники не обліковуються. Один користувач має одну роль; кожен Керуючий закріплений за одним готелем, а готель може мати кількох Керуючих.

## Спробувати локально через Docker

Для цього способу **не потрібно окремо встановлювати Java, Maven чи сервер бази даних**. Застосунок збирається й запускається в одному контейнері, а H2 зберігає дані у папці проєкту.

### 1. Встановіть і запустіть Docker

Встановіть [Docker Desktop](https://docs.docker.com/desktop/). Для Windows є [покрокова інструкція встановлення](https://docs.docker.com/desktop/setup/install/windows-install/), зокрема налаштування WSL 2. Проєкт використовує **Linux-контейнери**.

Запустіть Docker Desktop і дочекайтеся готовності рушія. Відкрийте термінал та перевірте:

```sh
docker version
docker compose version
```

### 2. Відкрийте папку проєкту

Розпакуйте отриманий архів із кодом або відкрийте наявну копію репозиторію. Перейдіть у корінь проєкту, де розташований `pom.xml`. Файли контейнеризації містяться в папці `docker/`: [Dockerfile](docker/Dockerfile) і [compose.yaml](docker/compose.yaml).

Наприклад, у PowerShell:

```powershell
cd C:\edu\wt_hotels
```

Якщо ви зберегли проєкт в іншому місці, підставте свій шлях. Усі наступні команди виконуйте з цієї папки.

### 3. Зберіть і запустіть застосунок

```sh
docker compose -f docker/compose.yaml up --build -d
```

Перший запуск потребує інтернету та може тривати кілька хвилин: Docker завантажує образи, Maven — залежності, після чого запускаються тести й збирається застосунок.

Переглянути стан і журнал запуску:

```sh
docker compose -f docker/compose.yaml ps
docker compose -f docker/compose.yaml logs -f hotels
```

Коли в журналі з’явиться `Started HotelsApplication`, відкрийте **[http://localhost:8081](http://localhost:8081)**. `Ctrl+C` завершує перегляд журналу, але залишає застосунок працювати.

## Перше налаштування

1. На першому екрані створіть **Адміна**: введіть email і пароль. Пароль — щонайменше 10 символів і не більше 72 байтів UTF-8; українські літери можуть займати більше одного байта.
2. У розділі **«Готелі»** додайте готелі мережі.
3. У розділі **«Користувачі»** створіть Адміністратора та Керуючих. Для кожного Керуючого виберіть його готель.
4. Увійдіть як Керуючий та додайте номери: назву або номер, кількість ліжок, ціну за ніч і оснащення.
5. Увійдіть як Адміністратор, відкрийте **«Знайти номер»**, виберіть дати та створіть бронювання.
6. Керуючий виконує **заселення → виселення → завершення клінінгу**. Після виселення дохід з’являється у звіті.

Готових облікових записів і стандартних паролів немає. Довідник ролей створюється автоматично під час запуску.

## Основні правила

- Бронювання діє від дати заїзду **до дати виїзду, не включаючи її**. Перед збереженням сервер повторно перевіряє перетини під блокуванням номера.
- Фізичні стани: **вільно → зайнято → клінінг → вільно**. Майбутнє бронювання зберігається окремо.
- Ціна проживання фіксується **при заселенні**. Подальша зміна ціни номера не впливає на це проживання.
- Облікова доба починається о **12:00 за Києвом**. Стани змінює Керуючий вручну; автоматичного заселення чи виселення немає.
- Валовий дохід записується **лише при виселенні**: зафіксована ціна × фактичні облікові ночі, мінімум одна ніч. Звіт відбирає записи за часом виселення.

## Зупинка, повторний запуск та оновлення

| Дія | Команда |
| --- | --- |
| Зупинити | `docker compose -f docker/compose.yaml stop` |
| Запустити після зупинки | `docker compose -f docker/compose.yaml up -d` |
| Перезібрати після зміни коду | `docker compose -f docker/compose.yaml up --build -d` |
| Переглянути останні повідомлення | `docker compose -f docker/compose.yaml logs --tail 100 hotels` |
| Видалити контейнер і мережу Compose | `docker compose -f docker/compose.yaml down` |

Compose використовує корінь репозиторію як контекст збирання та папку `data/` у корені для даних (`../data` відносно Compose-файлу). Назву Compose-проєкту зафіксовано як `wt_hotels`, щоб перенесення конфігурації не створювало інший набір контейнерів. Файл `.dockerignore` залишається в корені контексту збирання.

Файли в `data/` залишаються після зупинки та видалення контейнера. Для резервної копії зупиніть застосунок і скопіюйте **всю папку `data/`**.

## Налаштування

За замовчуванням нічого змінювати не потрібно:

| Параметр | Значення |
| --- | --- |
| Адреса | `http://localhost:8081` — доступ лише з цього комп’ютера |
| База даних | `data/hotels.mv.db` |
| Ключ підпису JWT | `data/jwt.key`, генерується автоматично |
| Часовий пояс | `Europe/Kyiv` |
| Строк дії JWT | 8 годин |

Docker за замовчуванням публікує застосунок на порту **8081**; усередині контейнера він працює на порту **8080**.

**Якщо порт 8081 зайнятий або заблокований**, у [docker/compose.yaml](docker/compose.yaml) замініть `127.0.0.1:8081:8080` на `127.0.0.1:8082:8080`, виконайте `docker compose -f docker/compose.yaml up -d` та відкрийте `http://localhost:8082`.

**Для перевірки зі смартфона** спочатку створіть Адміна локально, потім у довіреній локальній мережі змініть прив’язку на `8081:8080` і виконайте `docker compose -f docker/compose.yaml up -d`. Підключіть телефон до тієї самої мережі й відкрийте `http://IP-адреса-комп’ютера:8081`. Брандмауер має дозволяти цей порт у приватній мережі. Поточна конфігурація призначена для локальної демонстрації; публічне розгортання потребує HTTPS.

Для запуску Java-процесу доступні змінні `PORT`, `DB_URL`, `DB_PASSWORD`, `JWT_KEY_FILE`; значення за замовчуванням наведені в [application.yml](src/main/resources/application.yml). У Docker їх потрібно явно передавати через секцію `environment` у `docker/compose.yaml`. Звичайний файл `.env` сам по собі не передає ці параметри застосунку. Для зміни зовнішнього порту достатньо змінити прив’язку `ports`.

## Запуск без Docker та тести

Потрібен **JDK 17** і змінна `JAVA_HOME`, що вказує на його папку. Maven Wrapper уже є у проєкті й завантажує Maven 3.9.11 при першому запуску.

Windows / PowerShell:

```powershell
.\mvnw.cmd verify
.\mvnw.cmd spring-boot:run
```

Linux / macOS:

```sh
sh mvnw verify
sh mvnw spring-boot:run
```

`verify` запускає юніт-тести бізнес-логіки з Mockito, без Spring-контексту та реальної бази даних. Не запускайте одночасно Docker-версію і локальний Java-процес з однією файловою базою.

## Технології

**Java 17 · Spring Boot · Spring Security · Hibernate / JPA · H2 · Flyway · Maven · JUnit · Mockito · Lombok**

Фронтенд: **окремі HTML-сторінки, CSS, JavaScript ES modules**. Кожна сторінка підключає свій JS-модуль; спільна розмітка карток і форм зберігається в HTML-шаблонах. Усі HTTP-виклики зібрані в `core/rest.js`. Сервер приймає JWT і формує `HotelToken`; права та прив’язка до готелю читаються з бази для кожного запиту.
